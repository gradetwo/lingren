# Yeban Chinese Arrangement

中文人声编曲 skill：给中文歌词写旋律、配和声、做编曲与混音时用。核心是“一字一音”的咬合：歌词声调、节奏、语义须与旋律走向、律动、重音精准对上。以下规则来自实测教训，不是通用乐理复述。

## 真人感来自变化

- 音乐中的真人感来自疏密、高低、轻重、起伏等变化。任一维度长期不变，听感就假、就平。
- 疏密：时值长短变化、间隙疏密变化，不许全程等长快音节。
- 高低：音域起伏与轮廓变化，不许全局修平或长期平铺。
- 轻重：实词与虚字的轻重分位、音量曲线的段落起伏，不许统一压平。
- 起伏：段落情绪曲线（主歌收、副歌放、Climax 最大）与句内走向变化。
- 验收时四维各查一遍：谱面时值、音高轮廓、音量曲线、段落布局，任一维全程不变即返工。

## 创作中遇见夜半问题就地改进

- 创作过程中遇到夜半的问题就去改进和完善（Wang 2026-11-03 立规），不只记下来绕过去。
- 执行方式：制作 agent 在 REPORT 里单列一节写清现象、复现步骤、涉及文件与 workaround，制作用 workaround 先行、不等修复；修复走独立分支＋本地验证＋CI＋合入（TrackVolume 离线修复即此规实例）。
- 修复合入前，skill 里的 workaround 继续有效；修复合入后，skill 对应条目须更新为修复后行为。

## 先定创作路径

- 先词后曲：情感与意思最完整，词可自由发挥；难点是旋律易被字数绑架，写成念经或朗诵，改稿量大。
- 先曲后词（填词）：旋律优先，易抓耳；难点是在固定音符格子里找字，最怕“音多字少”（拖沓空洞）或“音少字多”（仓促赶拍）。
- 个人全流程创作时词曲一起写最自然，但须随手录音，灵感转瞬即逝。
- 本 skill 的默认立场：旋律服从歌词。把歌词硬贴到现成旋律上已被实测证伪（见“硬贴的教训”），冲突时改旋律，不硬贴。

## 字正：声调与旋律走向咬合

- 一声（高平）：旋律不要往下掉得太狠。
- 二声（上扬）：旋律尽量从低往高走。
- 三声（低降）：适合放在较低的音上。
- 四声（下降）：旋律从高往低走更自然。
- 不必苛求每个字完美，但关键字（易听错的名词、动词）务必检查。
- 验收：声调冲突 0，按字典声调与变调修正双标准审计（工具 `~/workspace/tools/tone_audit.py`）。
- 检验方法：写完一句，先用说话语调念一遍，再唱一遍，关键字变味即改。刻意倒字只许作为整体音乐形象清晰时的艺术处理，不许作为省事的借口。

## 呼吸：换气点是标点符号

- 优先在逗号、句号处换气；必须句中换时，尽量在并列词之间或虚词前偷气。
- 弱拍偷气：用 0.2–0.3 秒在弱拍快速无声吸气，不破坏律动；快歌每两小节弱拍可安排一次偷气。
- 原则意思优先：换气会切断一个完整词或意象时，宁可调整旋律或歌词，也不要硬换。
- 验收：全部换气落在歌词行边界，行内、词内零间隙。

## 轻重：字放在对的位置

- 实词（名词、动词、歌名核心词）放在重拍或长音上，听觉焦点落在关键信息上。
- 虚字（的、了、在、吗）放在弱拍或短音上，一带而过，不喧宾夺主。
- 转音、一字多音留给情绪最浓烈、最需要延展的地方。
- 句尾收束须为实词，不许用虚字凑韵脚，否则句尾疲软无记忆点。
- 验收：逐字核对自然朗读重读字与旋律强位，重音错位致语义扭曲即改。

## 线条感：不要打字机

- 中文以字为单位，易唱得一顿一顿。不要以为一个音符对一个字就万事大吉。
- 在字数框架内有意识地用休止符、连音制造语气起伏，不要每个字都实打实唱满。
- 抒情段落多做字与字之间的连音或滑音，让声音流淌，避免块状咬字。
- 验收：时值分布不得扎堆（任一 0.05 秒桶不得超过 25% 的音）；密度目标 ≤1.6 字/秒。

## 硬贴的教训（实测数）

- 把《时光》歌词 1:1 硬贴到转录旋律上：声调冲突粗算 53/79（67.1%），5 处换气全在行内（回|到、天|午后、遗|憾、错|过、住|手），密度 2.57 字/秒，51% 的音挤在 0.25–0.30 秒，间隙仅占全曲 3.7%。听感：平、赶、全程在唱无留白。
- 对照 folk-v5：208 音、194 秒、1.07 字/秒，间隙 28 处占 36.6%，最长 28.33 秒（间奏）。
- 结论：转录旋律的乐句结构属于原歌词，不属于新歌词。硬贴必然同时犯声调反向、换气切句、节奏机械三错。修复须重写旋律（DP 解法参考 `~/workspace/tools/rewrite_melody.py`，改动留清单与理由），不许只调参数或混音掩盖。

## 听感诊断顺序：先查谱词，再查参数

- 人声听感发平、赶、机械时，先查谱词对齐，再查 SoulX 参数或调用。顺序不可倒置。
- 先查四项：声调冲突审计（双标准）、换气是否全落行边界、时值分布是否扎堆、密度是否超 1.6 字/秒。
- 单轨干声音准好不排除谱词问题：模型唱准音高时，音高与字调反向会被完整唱出来，听感反而更平。
- 实测教训（midi-v1，2026-11-03）：初诊称“没给表现力信息＋严格乐谱时钟＋三遍求同＋中性 prompt”，排除 auto_shift 与 pitch_shift；Wang 指正后实测证实是谱词问题——声调冲突粗算 67.1%、5 处换气全在行内、51% 的音挤在 0.25–0.30 秒、密度 2.57 字/秒，而干声中位音准误差仅 6.3 音分。参数方向未动，改谱后审计归 0 才解决。

## 人声生成：几句一段（Wang 2026-11-03 立规）

- SoulX 一次生成不宜太长。整首一次生成，后段质量变差（误差累积）。
- 单句一段亦不可。逐句拼接，段接处有断的感觉。
- 取中间：一次生成几句，数句为一组，不整首一次，不单句一次。拼回时按谱面时间对齐。
- 实测（《时光》v3，2026-11-03）：整首一次生成后段变差；逐句拼接后段变差已解，但段接处断感重。
- 拼接验收：段接处不断、不断句意；后段质量不滑坡。两项有一项不过即返工。
- 此条取代 2026-11-03 早些的逐句生成口径。

## 人声生成：SVC 先造曲风 prompt（Wang 2026-11-03 立规）

- 适用情形：SoulX 输出带美声感、prompt 曲风与目标曲风不对应（目标流行，prompt 偏美声）时，先造曲风 prompt 再唱，不要直接调参数。
- 机制边界（先认清，再用）：SVC 保留源表演、只换音色；输入里无风格参考、风格标签、风格强度；唯一参考音频同时承载音色与风格；解耦是音色与语言内容，不是音色与风格。正向（美声源换音色）无用——美声成因全在表演层（起音慢、乐句拱形），换音色不动它们。
- 反向管线（可用）：源＝真实流行唱法表演（任何歌手）＋prompt＝本音色参考 → 输出＝本音色唱流行。曲风必须由真实流行表演提供，不能由参数凭空指定。
- 做法：选主流流行唱法录音（口语化、轻颤音、流行咬字），切 8–15 秒干净段落（混音须先人声分离＋去混响）；SVC 转本音色（女声目标 zh_prompt、男声目标 male-demo 窗口）；输出建成 SoulX prompt 对（wav 加标准预处理转录 meta，转录 ASR 重复字按标准流程原样用）；再按谱唱。
- SVC 事实：SoulX-Singer-SVC（Soul-AILab/SoulX-Singer，Apache-2.0），权重 model-svc.pt，公开下载无门控；默认 n_steps=32、cfg=3.0；输出 24kHz。
- 定规（Wang 2026-11-03）：SVC 一律 auto_shift 关，pitch_shift 一律 0，不补偿。同性别与跨性别都不补偿。音区由谱子层定，不在 SVC 层补。
- 最佳实践（Wang 2026-11-04）：尽量避免跨性别转换；谱子保证落在该性别合适音域（女声 C4 起、男声 C3 起）。依据：两测（女转女／女转男，2026-11-04）证实音高起主要作用，共振峰不完美是次要影响——同一女 prompt 在 60–72 是女声、在 44–56 是男声；男 prompt 在 60–72 整体男声但偏女声一点。
- auto_shift 缺陷（已定位，2026-11-03）：auto_shift 按 prompt 与目标的中位 F0 之比取整移调，无八度归一化；实测男＋13、女＋19，均为离调量（八度＋1、八度＋7），输出既不在原调也不在原调的任何八度上。决定性对照：同源＋同男 prompt，只改开关，关逐音偏差 −0.39～+0.46，开＋12.70～+13.35。不要用中位比公式现算移调量。
- 补偿口径变迁（记一笔，免反复）：2026-11-03 晚间曾定同性别＋0、跨性别约＋6（两声音 natural 中位差 5.91），后由“谱子音区放对就不需要补偿”取代。跨性别＋6 只在相对层合理（女版整体比男版高 6 个半音），不贴住目标中位；现已不用。
- 测试设计铁律（2026-11-03 G1 教训）：风格测试必须用流行歌自身的谱子＋分离原声作对照，不得用本歌谱子——本歌谱子本身可能带美声感，会混淆 prompt 效果。
- 实测状态（2026-11-03）：干净确认已交付（《孤勇者》自身谱子＋原声对照）；男声 f0fixed 通过；女声低音区像男声，解法转入谱子音区一节。

## 谱子音区按性别放（Wang 2026-11-03 立规）

- 女声放 C4 起，约 MIDI 60 起。男声放 C3 起，约 MIDI 48 起。谱子音区对了，就不需要补偿。补偿是事后补救，音区放对是事前正确。
- 翻唱固定旋律：旋律是定的，女声唱男声低音区旋律要么照原调唱（低 → 像男声），要么谱子层整体移调。移调在谱子层做，主唱和声一起移，不会三全音冲突。编曲时可选择转调，落在声音性别的合适区间。
- 个别音落到区间外时，谱子转调处理：整体移几个半音，把音区对齐到合适位置。转调比八度移调更细，主唱和声一起移，内部关系不变。
- 证据（2026-11-03）：同一张 f0fixed 谱子（44–56，全在 C4 以下），男声通过，女声像男声。差的就是音区与性别的匹配。
- 证据（2026-11-04，两测定稿）：同一女 prompt 在 60–72 是女声、在 44–56 是男声；男 prompt 在 C3 男声、C4 整体男声偏女声一点、C5 无明显女声（顶部破音，F0 顶部偏差实证）。结论：音高起主要作用，共振峰不完美是次要影响；最佳实践是尽量避免跨性别、保证落在合适音域（见 SVC 一节最佳实践）。
- 边界：音区是必要条件，不是充分条件。音色共振峰与唱法仍是独立变量。

## 人声后期：给合成人声赋予人味（Yeban 原生手段）

- 逐字音量塑形：不要用统一压缩器压平。主歌压低造倾诉感，副歌第一遍推大，最后一遍 Climax 推到最大，甚至允许轻微过载增撕裂感。
- 注意 Yeban 缺陷已修复（2026-11-03 合入主干 3d9bf598）：TrackVolume 自动化离线渲染不生效的问题已修，自动化泳道现可正常用。修复前用片段增益（clip gain）做的工程仍有效；新工程优先用自动化泳道。行为变化：此前写了 TrackVolume 自动化但被静默忽略的工程，修复后离线渲染声音会变（自动化开始生效）。
- 动态 EQ：通道条 DynEq（Q、ratio 已落地）用于齿音、鼻音过重频段的自动衰减，模拟麦克风前距离感变化。
- 切片人性化：长句拆成词或短语；重点词（倒流、路口、遗憾）单独微调音分与起始瞬态，打破完美节奏网格，制造抢拍或拖拍的人味。此项须逐词渲染或离线处理，未在管线内验证，列为待验证。
- 气口：乐句间隙无自然换气时补气口（采样或滤波噪声合成）。待验证。
- 尾音：直线拖音加缓慢 LFO 颤音（5–6 Hz，极小深度），避免死板延音。Yeban 暂无 LFO 调制，需离线处理或新效果，待验证。
- 共振峰：副歌高音区提亮用通道条 EQ 实现。不写插件名（Little AlterBoy、Vocal Rider 等不在 Yeban 内）。
- 顺序：先剪辑与自动化赋予人味，再谈空间。不要用混响掩盖苍白表演；后期修音工作量应占大头。

## 编曲配器：敢于做减法

- 钢琴分段 re-voicing：主歌简化，只留根音与简单柱式和弦，或极高音区零星单音点缀，给人声留中频空间；预副歌加密，引入跨八度琶音推情绪上行；副歌改柱式敲击，强调重拍。
- 低频：副歌 Sub Bass 严格跟和弦根音，补 80 Hz 以下真空；全部非贝斯乐器（含钢琴与人声）在 150–300 Hz 窄带衰减，消除中低频堆积浑浊。
- Pad 生命力：弦乐或合成器 Pad 挂慢速音量起伏，像呼吸一样有强弱；段落转换处用 Riser 或反向镲片造张力。静态铺底即使空间大也空洞。
- 微观节奏：不需全套鼓。Shaker 或闭镲以 16 分音符切分出现，音量极低，只填高频空隙并提供潜意识律动。
- 和声方法：和声按主唱平行三度生成，只取 36–160 音区音符；和弦从头设计（如 A–F#m–E–C#m–B 循环），尾段落回主和弦。
- 采样注意：VSCO2-CE 全量乐器受 8,000,000 帧单次装载上限截断高 velocity 层，须用修剪 SFZ（钢琴 69→11、贝斯 26→5 等量级），装载失败须为 0。

## 混音母带：分层与居中

- 分层混响：人声用短 decay 的 Plate 或 Room，增加贴耳感与厚度，务必比伴奏更干、更靠前；只在长音尾巴上送少量 Delay 到大厅混响造余韵；钢琴加 Slapback Delay 增质感；弦乐保持大空间衬托氛围。
- 声像：Kick、Bass、主唱必须居中；钢琴高音区向两侧铺开但不超过 75% 宽度；相关表恒正，避免单声道播放时相位抵消致声音消失或变虚。
- 总线：温和光电压缩 2:1–4:1，阈值刚好让指针在副歌时跳动 2–3 dB，把乐器胶合；饱和器或磁带谐波暖化数字生硬感（Yeban 有磁带饱和效果器）。
- 动态：峰值因数过高致播放器上忽大忽小，须控制瞬态，不只看整体电平。

## 交付前验收门

- 声调审计 0（双标准）；换气全落行边界；密度 ≤1.6 字/秒；时值无单桶 >25%。
- 逐字音量曲线已画（非统一压缩压平）；重点词已做切片人性化或明确记录未做。
- SoulX 多遍差异门全过（包络相关、F0 差、起音差，无比特相同对）；渲染收据干净（clipped 0、warnings 空）。
- .yeban 全部 stored 压缩；终混满幅 0；相关表正；会话已停并报 CU 花费。
- 乐谱字段格式：lyric、midi、start_s、dur_s、phoneme；和声与主唱同法；改动留清单。
